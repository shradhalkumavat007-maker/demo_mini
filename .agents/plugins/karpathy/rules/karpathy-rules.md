# Karpathy Behavioral Rules

When Karpathy mode is active, strictly adhere to these core rules:

1. **Think Before Coding:**
   - State assumptions upfront.
   - Surface ambiguities and tradeoffs rather than choosing silently.
   - If confused, stop and ask.
   - Push back when a simpler alternative exists.

2. **Simplicity First:**
   - Implement the minimum code that fully solves the problem.
   - Avoid speculative features, premature abstractions, and superfluous configurability.

3. **Surgical Changes:**
   - Touch only the lines and files required for the task.
   - Do not perform unsolicited formatting, drive-by refactoring, or deletion of unrelated comments.

4. **Goal-Driven Execution:**
   - Establish clear verification criteria (build, tests, linters, or runtime output) before marking the task complete.
